# IC-7300周波数・モード認識と交信済み局除外 (Rev.A v0.5.0)

## 対応範囲

- 対象: 初代IC-7300（M/S含む）/ Windows 10/11 / USB仮想COM CI-V。
- 送信処理は実装しない。CI-V `03h` で周波数、`04h` でモードを**読み取るだけ**。ポーリングは約1秒、COM番号はGUIで設定する。COMを共有する別アプリと同時使用する設計ではない。
- `CW` (`03h`) / `CW-R` (`07h`) は両方CWとして分類。ログ用modeは`CW`に統一。CW以外では自動選局候補を無効化する。
- 周波数からバンドを推定し、JARL 2026 ALL JA / 全市全郡のCWコンテスト使用周波数帯と照合。帯域境界500Hz以内は注意として自動候補選択を無効化（本判定は**法的な送信帯域保証ではない**）。
- IC-7300のバンド（1.9/3.5/7/14/21/28/50 MHz）のみ対象。144/430は対応しない。
- COM切断、読取失敗、周波数・モード変更が発生したら、直前の受信候補を破棄する。接続中でも**現在の周波数とモードが送信瞬間まで不変である保証はない**。自動送信連動時は必ず再検証すること。
- IC-7300のスプリット運用の送信VFOは現在未取得のため、自動送信は常に無効。将来の自動送信ではスプリット状態と送信側周波数も必ず検査する。

## 交信済み局リスト

内部SQLiteファイル `%LOCALAPPDATA%\JARL_CW_AutoContest\contest_log.sqlite3` にQSO履歴を保存する。ログウィンドウは約1秒ごとに更新。CSVとの互換出力 `%LOCALAPPDATA%\JARL_CW_AutoContest\logs\{年}_{大会}_{自局}.csv` も残す。

- 自局のコールサイン + コンテスト種別 + 開催期間(JST、開始を含み終了を含まず) + **バンド** + 相手局コールサインで完了QSOを照合。
- 違うバンドでは同じ局とのQSOを許可する。途中で切れた未完了QSOは除外対象にしない。重複QSOは履歴から削除せず残す。
- 開催期間は設定画面でユーザーが入力する。未設定時は自動的に「未交信」と見なすのではなく、交信済み判定を**停止**する。
- 同じ大会の別開催年は開催期間により分離。日付と時刻はJST `YYYY-MM-DD HH:MM` を使用。
- 原則としてログは追記方式であり、既存CSVの履歴行が書き換えられた場合は取り込みを拒否する。旧版CSVや外部から追記された完全なCSV行は取り込める。SQLiteとCSVの不一致を検出した場合、安易に履歴を削除せず原因を調査する。
- 既存CSVは周波数(Hz)列を持たず**バンド列のみ**である。v0.5.0以降に受信したCI-V周波数はSQLite側の追加列に記録し、GUIに表示。旧記録の周波数は`--`とする。推測補完しない。

## GUI利用手順

1. 設定ウィンドウで自局コールサイン、JARLコンテスト、送信NR、手動用バンドを入力。
2. 開催開始・終了をJSTで入力（例：2026-04-25 21:00 / 2026-04-26 21:00）。この日時は**例示**であり次回大会に流用しない。
3. IC-7300のドライバー導入後、Windowsのデバイスマネージャーで確認した `COM4` 等を入力、保存。
4. `接続・読取`を選ぶと周波数とモードを表示。利用できない場合は「CI-V停止」となり、設定上のバンド値がライブ値の代わりになることはない。
5. 周波数を7MHzから14MHzへ変えると、交信済み局の照合先も14MHzへ切り替わり、7MHzへ戻ると7MHzの記録を再利用する。手動QSO登録時も有効なCI-V周波数が得られていればそのバンドで記録する。
6. `交信ログ`は別ウィンドウで開き、周波数・バンド・コール・NR・RST・状態を表示。CSVを従来のログ集計/提出ドラフトに利用できる。
