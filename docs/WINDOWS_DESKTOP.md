# Windows デスクトップ版（v0.4.0）

## 配布と動作の区別

- Windows 10/11向けの単独実行EXE化を目標とする。
- GUIはPython標準の`tkinter/ttk`で作成。配布時はPyInstaller `6.22.3`（2026-11-05時点の安定版）でPythonとGUIランタイムを取り込み、**利用者側にPythonのインストールは不要**。
- **Windows用EXEはWindows上でビルドする必要がある**。Linux上でのソース実行・Tk UI試験はWindows EXEの生成・動作検証と同じではない。
- このGUIには現在、実機CW送受信・DeepCWライブ復号・交信自動決定の連動処理は接続していない。送信禁止のままとする。
- WindowsからIC-7300 USB Audio/CI-Vを扱うには、今後連動を実装する段階で無線機側の対応ドライバーおよび設定が必要。

## WindowsでEXEを作成

Python 3.13（64-bit、安定版）をビルド用PCにインストールし、PowerShellでZIPを展開したプロジェクトのルートから：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build_windows.ps1
```

初回ビルドではPyInstaller 6.22.3 / setuptools 81.0.0等をpipから取得する。
生成先（**Windows上で成功した場合**）：`dist\IC7300_CW_AutoContest.exe`
配布するのは上記EXEのみでよい。外部COMドライバーや音声ドライバー自体を同梱するものではない。

## ソースから実行

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m cwcontest desktop
```

## 画面の構成

1. **設定ウィンドウ**：自局コールサイン、参加コンテスト（ALL JA/全市全郡）、送信ナンバー（RSTの599を除いた値）、バンドを入力 →「設定を保存」。新規起動時は自局コールサインと交換番号を空欄とし、サンプル局の設定を使用しない。
2. **交信ログウィンドウ**：起動時に自動的に別ウィンドウとして開く。閉じても「交信ログを表示」で再表示可能。1秒ごとにファイル更新を検知し、一覧を自動更新する。
3. 交信成立を確認した際のみ、ログ画面の「相手局」「受信NR」「RST」を入力し「QSOを登録」。確認ダイアログで明示的に確認後、既存形式のCSVに追記する。**これはテスト/手動操作用であり、受信AIの自動確定処理ではない**。
4. 既存の`cwcontest`ログ集計・CSV出力コアをそのまま利用できる。コンテスト開催日時・参加種目・署名等の提出情報は従来の別JSON設定で管理され、GUIだけで提出ファイルは作成しない。

## ファイル位置・ログ更新の仕様

Windowsでは `%LOCALAPPDATA%\JARL_CW_AutoContest` に保存する。

- `settings.json`：自局設定。保存の際には原子的に置き換える。
- `logs\2026_ALL_JA_JA1AAA.csv`：例。`年_コンテスト_コールサイン.csv` に分割。ログにはJST時刻、バンド、CW、相手局、送受信RST・ナンバー、完了フラグが追記される。実ファイル名は自局設定と現在年から決まる。
- 送信ナンバー変更後も過去のログ行は変更しない。既存CSVの列順は従来と同じ。
- ログは1秒周期で監視。変更時にファイルを再読込する。別プロセスからの追記でもファイルが完全なCSVとして保存されていれば更新できる。
- `重複候補`は同一バンド・相手局の簡易表示であり、コンテスト規約に従った最終得点・有効期間・正式な重複判定ではない。
- ログ確定を実行する他モジュールには、`DesktopStorage.append_qso(settings, qso)`を公開。今後、実機の承認済みQSO状態機械の完了後にこれを呼び出す。
